      sizeLimit on disk is not a hard quota

      The kubelet measures the volume periodically and evicts the pod once it is over the limit. A fast writer can overshoot first. The app never sees "disk full".

      The scheduler ignores sizeLimit. Only ephemeral-storage requests reserve disk on a node.

      Disk writes use page cache

      Files written to disk pass through the page cache, which is charged to the container's memory cgroup. It is reclaimable, so it shows as high memory use but rarely causes OOM kills.

      tmpfs is real RAM

      Every file in a medium: Memory volume counts as container memory and cannot be reclaimed without deleting it.

      sizeLimit is the tmpfs size. Writes past it fail with ENOSPC; no eviction. Without sizeLimit, the tmpfs is sized to the pod memory limit, or to node allocatable memory if there is none.

      tmpfs data survives container restarts and does not count toward ephemeral-storage.

      Who goes first under node pressure

      • Kernel OOM killer uses oom_score_adj: BestEffort 1000 (first), Burstable 2–999, Guaranteed −997 (last).
      • kubelet eviction ranks by usage above request, then priority class, then amount above request.
      • Ephemeral-storage settings do not change the QoS class.

      Pods without memory limits

      The container cgroup has no cap, but all pods sit under the kubepods cgroup, capped at node allocatable memory. Pods normally run without swap.

      The kubelet checks memory.available about every 10s (default threshold 100Mi). Fast growth reaches the kernel OOM killer first.

      For many pods with a 3G cache and no memory limits

      Keep the disk-backed cache at 3Gi. Add memory requests/limits and ephemeral-storage requests/limits to every pod. Use tmpfs only if disk I/O is a proven bottleneck.

      resources:
  requests:
    cpu: "500m"                 # observed usage
    memory: "2Gi"               # observed p95
    ephemeral-storage: "3.5Gi"  # cache + logs + writable layer
  limits:
    memory: "3Gi"               # p95 + 30-50% headroom
    ephemeral-storage: "4Gi"
volumes:
- name: cache
  emptyDir:
    sizeLimit: 3Gi

      Most important: set the app's own cache maximum below sizeLimit (about 2.4–2.5Gi for 3Gi). Eviction then becomes a safety net that never fires. Load the "Fix" scenario above to see it.

      Rollout steps

      1. Measure first with kubectl top pod and kubelet stats. Base limits on real usage.
      2. Check node capacity: total ephemeral-storage requests must fit node allocatable storage, with margin above the 10% eviction threshold.
      3. Enforce defaults with a namespace LimitRange; optionally a ResourceQuota on requests.ephemeral-storage and limits.memory.
      4. Test on one node with scripts/emptydir-scenarios.sh, then roll out gradually.

      Minimum memory limit

      Disk I/O

      Kubernetes does not limit IOPS or bandwidth per pod by default. A heavy cache writer slows neighbors' reads, writes and logging, and etcd on control-plane nodes.

      Inodes

      sizeLimit counts bytes, not files. Millions of small cache files can exhaust inodes while space remains, which also triggers DiskPressure (nodefs.inodesFree<5%).

      Priority classes

      Within the same QoS class, a higher-priority pod survives longer. If cache-heavy pods outrank their neighbors, the neighbors are evicted first.

      Mass refill

      Pods evicted together restart with empty caches and refill at the same time, which can saturate node disk I/O.

      Namespace defaults

      A LimitRange can silently apply default limits the app team doesn't expect.

      Alternative

      A PVC or generic ephemeral volume gives a hard size limit enforced by the filesystem and keeps cache I/O off the node root disk.

      Model assumptions: default kubelet hard-eviction thresholds (nodefs.available<10%, memory.available<100Mi), Kubernetes 1.22+ tmpfs sizing, all pods on the node identical, container logs and kubelet polling overshoot not counted. Real clusters can differ; confirm with the test script on a test node.
